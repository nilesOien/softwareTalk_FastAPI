Aside : git hooks

  • ruff exits with zero status only if the Python code checks are OK
  • pytest exits with zero status only if the unit tests are OK
  • A git hook is a script with a very specific name that exits with zero status only if if everything is OK.
  • git actions can only proceed if the hook passes (exits with zero)
Below is an example that exits with 0 only if ruff and pytest pass. If this script appears in the git repo root directory as ../.git/hooks/pre-commit then you can't commit unless ruff and pytest pass their tests.

You can't check the hook in to that position for security reasons, so you have to link it into place. 


$ cat preCommitHook.sh
#!/bin/bash

# Script that runs unit tests and ruff code tests.
# Can be used as a git hook. To do that it needs
# to be installed as a hook with :
#
# $ cd ../.git/hooks/
# $ ln -sf ../../section_06_unit_tests_and_git_hooks/preCommitHook.sh pre-commit
#
# Once this is installed as a pre commit hook, both
# unit tests and ruff code check have to pass for
# git to accept a commit. Hook scripts have to exit
# with 0 status for the requested action to go ahead.
# It's also possible to have pre-push hooks, I just like
# pre-commit hooks more.

# Make sure we're in the right directory.
if [ -d section_06_unit_tests_and_git_hooks ]
then
 cd section_06_unit_tests_and_git_hooks
fi

final_exit="0"
# Run unit tests.
# They fail if they have non-zero status.
echo Running unit tests...
uv run pytest -v
status="$?"
if [ "$status" -ne 0 ]
then
 echo pytest unit tests failed
 final_exit="-1"
fi

# Run ruff code checks - similar
echo
echo Running code checks...
uv run ruff check
status="$?"
if [ "$status" -ne 0 ]
then
 echo ruff code check failed
 final_exit="-1"
fi

# Say something
if [ "$final_exit" -eq 0 ]
then
 echo git hook : Tests passed, commit accepted
else
 echo git hook : There were issues, commit rejected
fi

# Exit with status that git will use to
# evaluate the commit.
exit "$final_exit"
